# US-01.03 — Configurar un proyecto · Refinamiento

Sprint: SPRINT-001

Absorbe a US-01.07 (consultar la configuración) y US-01.08 (modificar parámetros).

## Precondiciones
- El proyecto existe y el llamante tiene acceso.
- Para modificar: rol `owner` en el proyecto o rol global `admin`. Leer basta con `member`.

## Flujo
1. `acm_project_config_get(project_id)` devuelve cada parámetro con: valor actual, valor por defecto, tipo, valores permitidos, si requiere recarga, descripción y consumidor.
2. `acm_project_config_set(project_id, changes)` recibe un objeto `{parametro: valor}`.
3. El servicio valida **todos** los cambios antes de guardar ninguno.
4. En una transacción `BEGIN IMMEDIATE` sobre `project.db` guarda los valores, `updated_at` y `updated_by`.
5. Devuelve la configuración efectiva y la lista de parámetros cambiados que requieren recarga.

## Alternativas
- `changes` vacío: no escribe nada y devuelve la configuración actual.
- Poner un parámetro a su valor por defecto: se guarda de forma explícita.

## Errores
- `INVALID_ARGUMENT` con parámetro y motivo: parámetro desconocido, tipo incorrecto, fuera de rango o valor no permitido. Si hay algún error no se guarda nada.
- `FORBIDDEN` si un `member` intenta modificar.
- `NOT_FOUND` si el proyecto no existe o no es accesible (como US-01.02).

## Reglas
- Esquema de configuración del proyecto (versión 1):

  | Parámetro | Tipo | Por defecto | Permitido | Requiere recarga | Consumidor |
  |-----------|------|-------------|-----------|------------------|------------|
  | `sqlite.synchronous` | enum | `FULL` | `FULL`, `NORMAL` | sí (conexiones nuevas) | capa de datos (ADR-013) |
  | `context.max_tokens` | int | 8000 | 256..200000 | no | pendiente: servicio de contexto (US-35.08) |
  | `decision.engine_order` | lista | `["rules","jev","ollama"]` | subconjunto sin repetidos de {rules, jev, ollama}, no vacío | no | pendiente: router de inferencia (ADR-015) |

- La configuración vive en la base del propio proyecto (`project.db`, tabla `config`): pertenece solo a ese proyecto (CA-05).

## Validaciones
- Todas las validaciones se hacen antes de abrir la transacción de escritura.
- Los valores se guardan como JSON y se validan también al leer. Un valor corrupto en la base se reporta como error de integridad, no se ignora.

## Casos límite
- `context.max_tokens` = 256 o 200000 se acepta; 255 o 200001 se rechaza.
- `decision.engine_order` con duplicados o vacío se rechaza.
- Un cambio válido y otro inválido en la misma petición: se rechaza todo y no se guarda nada.
