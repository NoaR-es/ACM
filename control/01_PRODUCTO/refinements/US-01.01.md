# US-01.01 — Crear un proyecto · Refinamiento

Sprint: SPRINT-001

Absorbe a US-01.04 (B:US-01.01): sus criterios CA-01.04-01..04 se verifican aquí.
Diseño: ADR-013 (SQLite), ADR-014 (MCP, `project_id` explícito), ADR-011 (todo en SQLite).

## Precondiciones
- El llamante está identificado como un principal registrado en la base global. En SPRINT-001 el principal lo fija la configuración (`ACM_PRINCIPAL`, por defecto `local-admin`); la autenticación con tokens llega con EPIC-20.
- El principal tiene el rol global `admin`, que es el que permite crear proyectos.
- El directorio de datos (`ACM_DATA_DIR`) existe o puede crearse, y la base global está migrada.

## Flujo
1. El agente invoca la herramienta MCP `acm_project_create` con `key` (identificador), `name` y, opcionalmente, `description`.
2. El servicio valida `key` y `name`.
3. Comprueba que no exista otro proyecto con ese `key`.
4. Crea el directorio `<data_dir>/projects/<key>/` y la base `project.db`, y aplica las migraciones de proyecto.
5. En una transacción `BEGIN IMMEDIATE` sobre la base global registra el proyecto y la pertenencia del creador como `owner`.
6. Devuelve `project_id` (= `key`), `name`, `description`, `created_at`, `created_by` y la ruta de la base.
7. El proyecto aparece en `acm_project_list` y puede abrirse con `acm_project_open`.

## Alternativas
- Sin `description`: se guarda como cadena vacía.
- El llamante no es `admin`: se rechaza con `FORBIDDEN` y no se crea nada.

## Errores
- `INVALID_ARGUMENT` indicando el campo (`name` o `key`) y el motivo: nombre vacío o solo espacios, nombre de más de 120 caracteres, `key` con formato inválido.
- `ALREADY_EXISTS` si el `key` ya existe (en el registro o como directorio).
- `STORAGE_ERROR` si falla la creación del directorio o de la base, o el registro global. El mensaje es recuperable ("reintenta; no se ha creado nada").

## Reglas
- `key`: `^[a-z][a-z0-9-]{1,39}$`, inmutable. Es el `project_id` que usan todas las herramientas.
- `name`: se recortan los espacios de los extremos y debe quedar con 1 a 120 caracteres.
- Atomicidad: si falla el registro global, se borra el directorio creado; si falla la creación de la base, no se registra nada (CA-04).
- Toda escritura usa `BEGIN IMMEDIATE`, y `foreign_keys=ON` se activa en cada conexión (ADR-013).
- El error llega al agente con código y motivo explícitos (GAP-007).

## Validaciones
- Unicidad de `key` en la base global (`UNIQUE`) y comprobación previa del directorio.
- Tipos de `key`, `name` y `description` validados en la frontera MCP (esquema de la herramienta) y en el servicio.

## Casos límite
- Dos creaciones simultáneas con el mismo `key`: solo una tiene éxito y la otra recibe `ALREADY_EXISTS`.
- `name` con 120 caracteres se acepta; con 121 se rechaza.
- `key` en mayúsculas o con guion bajo se rechaza (no se normaliza en silencio).
- Directorio residual sin registro (por una caída anterior): se trata como `ALREADY_EXISTS` y se registra en el log para investigarlo.
