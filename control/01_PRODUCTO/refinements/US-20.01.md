# US-20.01 — Gestionar roles · Refinamiento

Sprint: SPRINT-004

## Precondiciones
- Principal admin (roles globales) o admin/owner del proyecto (roles de proyecto).

## Flujo
1. Roles definidos: globales `admin` | `user`; de proyecto `owner` | `member` (`acm_principal_list` los devuelve).
2. Un admin cambia el rol global con `acm_principal_set_role`.
3. Un admin o un owner asigna o retira miembros con `acm_member_set` / `acm_member_remove`.
4. El cambio rige en la siguiente petición: los permisos se consultan en cada operación.

## Alternativas
- `acm_member_set` sobre un miembro existente cambia su rol.

## Errores
- Rol desconocido → `INVALID_ARGUMENT`.
- Retirar el rol admin al último admin, o dejar un proyecto sin owner → `FAILED_PRECONDITION`.
- Sin permiso → `FORBIDDEN`; proyecto no accesible → `NOT_FOUND`.

## Reglas
- Todos los cambios pasan por MCP o CLI y quedan en `mcp_audit` con sus argumentos (CA-04).
- US-20.06 (B:US-16.03, asignar roles a usuarios y agentes) está fusionada aquí.

## Validaciones
- `principal_id`: `^[a-z0-9][a-z0-9._-]{1,63}$`.

## Casos límite
- Un admin es `admin` en todos los proyectos aunque no sea miembro.
