# US-21.03 — Recuperar estado tras reconexión · Refinamiento

Sprint: SPRINT-006

## Precondiciones
- El cliente guarda el último `seq` aplicado.

## Flujo
1. Al reconectar envía `after` = último `seq`.
2. El servidor le envía en orden todos los eventos visibles posteriores.
3. Si ya se purgaron, envía `{"type":"resync"}` y el cliente recarga el estado por REST.

## Alternativas
- REST `GET /api/v1/events?after=`.

## Errores
- `after` inválido → `resync`.

## Reglas
- Sin huecos ni duplicados: `seq` estrictamente creciente y el cliente ignora `seq` ≤ el último aplicado.

## Validaciones
- —

## Casos límite
- Estado final reconstruido a partir de los eventos = estado del servidor (verificado con el Kanban).
