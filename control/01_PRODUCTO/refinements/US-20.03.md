# US-20.03 — Gestionar tokens · Refinamiento

Sprint: SPRINT-004

## Precondiciones
- Principal admin (crear tokens; revocar los ajenos). El principal destinatario existe.

## Flujo
1. `acm_token_create(principal_id, name)` (o `acm token create` en el servidor) genera `acm_<256 bits aleatorios>` y lo devuelve **una sola vez**.
2. ACM guarda solo el hash sha256, un prefijo visible de 12 caracteres, el principal, el nombre y quién lo creó.
3. En cada petición HTTP se valida el token contra la base y se anotan `last_used_at` y `use_count`; la auditoría guarda el `token_id` de cada invocación.
4. `acm_token_revoke` lo revoca y la siguiente petición ya recibe 401.

## Alternativas
- `acm_token_list`: los tuyos, o todos si eres admin; nunca el secreto.

## Errores
- Token desconocido o revocado → HTTP 401 `UNAUTHENTICATED`.
- Crear un token para otro sin ser admin, o revocar uno ajeno sin serlo → `FORBIDDEN`.
- Principal inexistente → `NOT_FOUND`.

## Reglas
- El token autoriza con los roles actuales de su principal (CA-01).
- La auditoría redacta cualquier clave `token`/`secret`/`password` en argumentos y resultados.
- US-20.09, US-20.10 y US-20.11 (B:US-16.06..08: tokens por agente, revocación inmediata, uso registrado) están fusionadas aquí.

## Validaciones
- `name`: 1..80 caracteres.

## Casos límite
- Revocar un token ya revocado es idempotente.
