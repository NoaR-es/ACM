# US-14.04 — Conectarse a ACM mediante MCP · Refinamiento

Sprint: SPRINT-002

Origen B:US-15.01 sin criterios (GAP-001): se definen aquí.

## Criterios de aceptación
- CA-01: Un agente se conecta al servidor MCP de ACM por Streamable HTTP en `/mcp/` y puede invocar herramientas.
- CA-02: Un agente se conecta por stdio lanzando `acm mcp-stdio` y puede invocar herramientas.
- CA-03: Al conectar, el agente recibe `instructions` que explican cómo usar ACM (skills y `project_id`).

## Precondiciones
- `acm serve` en marcha (HTTP) o el comando `acm mcp-stdio` disponible (stdio).

## Flujo
1. El cliente MCP abre la conexión (HTTP o stdio).
2. Recibe la versión negociada, las capacidades y las `instructions`.
3. Invoca herramientas.

## Alternativas
- Clientes con protocolo con handshake (2025-xx): el SDK los admite; se prueba la versión que negocia el cliente oficial (2026-07-28).

## Errores
- Puerto ocupado o directorio de datos no escribible → el proceso no arranca y muestra el motivo.

## Reglas
- Topología de ADR-014: un proceso sirve `/api` y `/mcp`.

## Validaciones
- `/api/health` confirma `foreign_keys` y WAL antes de aceptar trabajo.

## Casos límite
- HTTP sin autenticación: solo escucha en 127.0.0.1 (VULN-001).
