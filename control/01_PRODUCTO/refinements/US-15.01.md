# US-15.01 — Registrar una Skill · Refinamiento

Sprint: SPRINT-002

En este sprint, "registrar" = añadir la skill al catálogo oficial versionado con el código (`src/acm/skills/<nombre>/SKILL.md`, ADR-008). El registro en caliente de skills propias de cada proyecto es POST-MVP (EPIC-53).

## Precondiciones
- La skill es una carpeta con `SKILL.md` en el directorio del catálogo.

## Flujo
1. ACM carga el catálogo al arrancar (y con `acm_skills_reload`).
2. Valida el frontmatter de cada skill.
3. Activa las válidas y deja las inválidas en `rejected` con su motivo (visible en `acm_system_info` y `acm_skills_reload`).

## Alternativas
- Una skill cuya dependencia no está activa también se rechaza (en cascada).

## Errores
- Motivos de rechazo:
  - falta el frontmatter;
  - `name` no coincide con la carpeta;
  - falta `description`;
  - `version` no es semver;
  - `capabilities` no es una lista no vacía;
  - `dependencies` no es una lista;
  - hay subcarpetas;
  - nombre de archivo inválido;
  - se superan los límites de SEP-2640.

## Reglas
- Frontmatter obligatorio: `name`, `description`, `version` (X.Y.Z), `capabilities` (lista no vacía) y `dependencies` (lista de skills del catálogo).

## Validaciones
- Límites de SEP-2640: 512 archivos y 16 MiB por skill.

## Casos límite
- Dependencia circular o hacia una skill rechazada → rechazo en cascada.
