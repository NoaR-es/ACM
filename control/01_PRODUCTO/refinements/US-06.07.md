# US-06.07 — Kanban de uno o varios proyectos · Refinamiento

Sprint: SPRINT-007

## Precondiciones
- Sesión iniciada en la interfaz con un token `acm_` válido (US-31.01, ADR-017).
- El operador tiene acceso a uno o más proyectos.

## Flujo
1. El operador abre el Kanban y marca los proyectos (`#/kanban?projects=a,b`).
2. La interfaz pide `GET /api/v1/kanban?projects=…` y agrupa una columna por estado.
3. Cada tarjeta lleva la franja de color y el nombre de su proyecto.
4. El operador alterna entre vista mezclada y un carril por proyecto.
5. Arrastra (o usa «Mover a…» con teclado) a una columna permitida: `POST …/status`.

## Alternativas
- READY solo por el gate (`POST …/ready`).

## Errores
- Movimiento no permitido: la columna se marca como no válida y, al soltar, se explica el rechazo.

## Reglas
- Transiciones = `STORY_TRANSITIONS` del backend; el cliente solo las usa para guiar, el servidor decide.
- Colores de proyecto estables (`projectIndex`) y con contraste AA (US-31.07).

## Validaciones
- Parámetro `projects` limitado a proyectos accesibles; los ajenos se ignoran sin revelarlos.

## Casos límite
- Un solo proyecto seleccionado: sin carriles ni franja redundante.
- Columnas vacías visibles para poder soltar.
