# US-18.02 — Mantener transacciones consistentes · Refinamiento

Sprint: SPRINT-001

## Precondiciones
- Conexión abierta con la configuración de ADR-013 (`isolation_level=None`).

## Flujo
1. El código de dominio abre `with db.write() as conn:`, que ejecuta `BEGIN IMMEDIATE`.
2. Ejecuta todas las sentencias relacionadas.
3. Al salir del bloque sin excepción → `COMMIT`; con excepción → `ROLLBACK` y se relanza la excepción.

## Alternativas
- Solo lectura: `with db.read() as conn:` sin transacción de escritura (WAL permite leer mientras otro escribe).

## Errores
- `database is locked` al iniciar `BEGIN IMMEDIATE` con el `busy_timeout` ya agotado → hasta 3 reintentos con espera creciente (50, 100 y 200 ms); después, `STORAGE_ERROR` "base de datos ocupada".
- Cualquier excepción dentro del bloque → rollback completo.

## Reglas
- Prohibido `BEGIN DEFERRED` para escrituras (SPIKE-001 E3).
- Prohibido `executescript` dentro de una transacción de dominio: hace `COMMIT` implícito.
- No se anidan transacciones de escritura: abrir `write()` dentro de otro `write()` en la misma conexión es un error de programación y se detecta.

## Validaciones
- El gestor verifica `conn.in_transaction` antes y después para detectar anidamientos o transacciones colgadas.

## Casos límite
- Excepción después de varios INSERT/UPDATE → ninguno persiste.
- Excepción de tipo `KeyboardInterrupt` o `SystemExit` → también rollback.
- Contención entre procesos: dos escritores con `write()` a la vez → ambos confirman, uno después del otro; no se pierde ninguna actualización.
